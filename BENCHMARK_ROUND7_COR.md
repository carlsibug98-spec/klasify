# Klasify OCR — Round 7 benchmark (student COR)

Date: 2026-10-29 · Tree: current workspace · OCR proxy: tesseract 5.5.0
stand-in for the native PP-OCR engine (no native runtime in the test VM)

## Why round 7

Rounds 1–4 measured weekly-grid and free-form schedule photos. The most
common real import for a university student is neither: the **Certificate of
Registration (COR)**, the enrolment form every Philippine school prints with
one row per subject and a `hh:mm AM - hh:mm PM / Day` schedule cell. Round 7
adds a dedicated six-sample COR benchmark, wires the same samples into
bench5 (speed) and bench6 (accuracy), and fixes what the samples exposed.

## The six samples (57 ground-truth classes)

| fixture | style | truth rows | what it probes |
|---|---|---|---|
| `cor_registry_clean.png` | clean registrar scan | 7 | continuation row (second meeting), Gym/Coach faculty |
| `cor_labs_online.png` | labs + online columns | 10 | `tba` cells, `MacLab`/`Lab 2` rooms, `IT Elec2`/`IT FE1` codes |
| `cor_phone_skewed.jpg` | tilted phone photo | 10 | perspective distortion, wood background |
| `cor_phone_blurred.png` | out-of-focus shot | 10 | sharpen rescue pass (0/10 → 10/10 when rescued) |
| `cor_lowres.png` | 720px cheap camera | 10 | hard floor: interpolation destroys thin glyphs |
| `cor_dim_noise.png` | dim evening shot | 10 | ISO noise, warm cast |

Ground truth: `test/fixtures/cor_truth.json` (subject, day, start, end,
room, faculty per class). The images are the uploaded samples plus
degraded variants generated by `scripts/make_cor_fixtures.py` in the
project workspace (blur radius and noise were tuned so each variant
isolates one realistic capture fault).

## Baseline → round-7 results (harness-measured, tesseract stand-in)

Micro-averaged over the six fixtures, greedy 1-to-1 matching on
day + interval overlap + subject similarity ≥ 0.34:

| metric | baseline | round 7 |
|---|---|---|
| recall | 0.404 | **0.702** |
| precision | 0.622 | **0.870** |
| f1 | 0.489 | **0.777** |
| subject exact | 0/40 | 34/40 |
| day/start/end | 23/23/23 | 40/40/40 |
| room ok | 21 | 35 |
| professor ok | 21 | 37 |

Per fixture (round 7): clean 7/7, labs 10/10, blurred 10/10 (baseline 0/10),
dim 10/10 (baseline 7/10), skewed 2/10, lowres 1/10.

The two remaining hard fixtures are honest limits of the tesseract stand-in:
the skewed photo's 7° tilt plus perspective misaligns OCR bands across rows
(the native PP-OCR det+cls engine re-angles text boxes and does better on
device), and the 720px capture simply lacks the pixels for thin glyphs.
Both leave flagged, reviewable rows where the OCR read anything at all —
the review screen exists for exactly this.

## What changed

- **`cor_schedule_parser.dart`**
  - `looksLikeCor` now also fires on ≥ 2 COR-shaped schedule cells beside
    the COR column vocabulary (`Rm`, `Prof.`, `Faculty`, `Units`,
    `Registrar`), because photographed forms garble the printed title and
    the header band. Plain timetables still never match (their times never
    carry the `/ Day` cell).
  - The schedule-cell regex tolerates `09: 30` (space after colon),
    `05 00 PM` (dropped colon), `08.30`, and tight slashes (`PM/Fri`).
  - Day cells tolerate one-character OCR slips (`Tuo` → Tue, `Wen` → Wed)
    when the closest weekday is unique; ambiguous slips stay unparsed.
  - Cell separators and underline filler (` | `, `BSIT-2A _`) are stripped
    before parsing, so subjects carry no pipe junk.
  - Code letter/digit slips recover (`PEO?` → PE0, `IT FEL` → IT FE1) only
    when the plain code parse already failed.
  - A row whose description survived but whose code column did not (skewed
    and soft photos) is emitted with its own subject and flagged for review
    instead of being dropped. A line with no subject text of its own still
    continues the row above it (the second-meeting rule), and room/faculty
    fragments are never mistaken for subjects.
  - Rooms are normalized (`lab2` → `Lab 2`, `maclab` → `MacLab`).
- **`ocr_image_preprocessor.dart`**
  - New `sharpen` variant (3x3 unsharp mask, amount 1.5) and a `softness`
    metric (3x3 Laplacian variance of the enhanced grayscale) returned on
    `PreparedOcrImage`. Calibrated on the COR fixtures: crisp pages measure
    1300+, soft ones under 700.
- **`schedule_ocr_service.dart`**
  - The scan cascade gains a **Sharpen rescue** pass: when the enhanced
    pass reports softness < 800 and nothing parses strongly yet, the
    unsharp variant runs as one more candidate and the ParseChain score
    picks the winner. Sharp pages never pay the extra call.
- **Benchmarks**
  - New `test/bench7_cor_accuracy_test.dart`: the six COR samples through
    the real pipeline, scored with the bench6 matcher plus room/professor
    field checks, and a regression floor (micro-recall ≥ 0.60).
  - `bench5_scan_speed_test.dart` and `bench6_accuracy_test.dart` include
    the six COR samples (bench6 also scores their room/faculty labels).
- **`tool/cor_harness/`** — a Flutter-free harness that runs the real
  parser chain on real tesseract output for the six fixtures, so the
  benchmark VM can verify parser changes without the Flutter SDK.

## Reproduce

```bash
flutter test test/bench7_cor_accuracy_test.dart   # COR accuracy (6 fixtures)
flutter test test/bench6_accuracy_test.dart       # accuracy incl. COR set
flutter test test/bench5_scan_speed_test.dart     # speed incl. COR set
dart run tool/cor_harness/bin/harness.dart        # VM-side quick check
dart run tool/cor_harness/bin/regression.dart     # parser regression checks
```

`build/bench7_cor_accuracy.json` (and the bench5/bench6 outputs) carry the
per-fixture numbers, parsed rows, and matched pairs for every run.
